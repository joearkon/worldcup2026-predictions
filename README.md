## 这是什么

2026 美加墨世界杯（48 队 / 104 场）期间，每天对当日比赛做赛前预测，输出独立的预测报告页，并在赛后做复盘。整站是**纯静态**页面（HTML/CSS/JS，无后端、无构建），部署在 Cloudflare Pages。

- **不是投注工具**，是一个把"足球判断"结构化、可回溯、可验证的娱乐项目。
- 所有比分预测都给**主预测 + 次选**双锚，赛后按口径自动算命中率。

## 功能

- **📅 赛程时间轴**：小组赛全 72 场（北京时间），按日期分组、今日自动定位，已预测场次可点开完整报告。
- **🏆 战绩看板**：`比分命中率`（比分为王，仅精确/次选算命中）+ `方向命中率`（胜平负）双指标；下方「战绩流水」按最近在前列出已开赛场次的 预测/次选/实际/命中。
- **🌍 小组积分榜**：从已完赛结果实时计算 赛/胜/平/负/净胜/积分，每组前 2 标绿（出线区）。
- **📊 单场预测报告**：五维评判 + 比分概率分布 + 关键先生 + 最终评判 + 盘口（欧盘/亚盘）+ 资料来源。
- **⚖ 赛后复盘**：对值得复盘的场次做差距拆解（判断误差 vs 临场变故），沉淀进复盘台账。
- **🌙/☀️ 暗/亮主题**切换（localStorage 记忆）。

## 预测方法论

**五维框架（骨架，定方向与剧本）**：① 阵容硬实力 ② 状态与近况 ③ 历史交锋与魔咒 ④ 赛场因素 ⑤ **软性指标**（球队心气/韧性/动机/板凳深度/团队凝聚等无形项——**只放软性，绝不含盘口**）。

**🎭 球队画像八维（0616 用户定 · 数据中心 `team_profiles.md`）**——第一轮定位=**画像采集窗**：别纠结比分命中率（足球低比分 + 首轮偶然性高），抓**胜负方向**——方向错 = 对球队的定性判断错，才会污染第二三轮（画像带着走，比分错多是运气）。每队画像采集八维、两层：

- **气质层**：① 状态　② **打法风格**（传控/防反/高压/高空/速度/铁桶——记它为预判**打法相克**：传控撞铁桶=低分闷局[西 0-0 佛]、高空撞防空弱=能打穿[挪 vs 伊]、速度撞高位线=打身后）　③ 教练激进/保守　④ **血性·放得开**（落后能否反扑、实力释放没——这届首轮最大分水岭）
- **成色层**：⑤ **防线成色**（铁桶/会漏球/高位身后 = 「铁桶 vs 鱼腩」画像锚）　⑥ **门将**（X-factor 级屡次改变结果）　⑦ **核心依赖**（单核可盯死 / 体系均衡）　⑧ **守成力**（领先守得住 / 易被扳平崩盘）
- **画像 > 盘口**：第二轮起决策重心从"盘口热门"挪到"画像里的对手成色"。打法相克常比谁强谁弱更早锁定比赛形态（对攻/闷局/压制）。
- **首次实战（0617）**：用八维覆盖盘口预测——法塞 2-1→1-1、阿根廷 2-0→1-0（均"控球/天赋打铁桶"压低），奥约主同次微调，伊挪八维=盘口（高空克防空）。建立"画像 vs 盘口"对照实验，赛后验机制。

**⑥ 本届小组赛表现 + 出线处境（仅第2轮起启用 · 0615 用户拍板新增/加权）**：球队已踢过本届小组赛（每队 ≥1 场）后新增此维。**核心定位：⑥是"已兑现的真实力"读数，权重 ≥ ①阵容硬实力**——①是赛前假设，⑥是正赛已发生的事实（阵容真实状态/进攻成色/防守韧性/临场调度），**已兑现 > 假设**。**第1轮无历史，不用此维**。数据底座=`stats/matches.json` + `team_profiles.md` + 小组积分形势。

- **🔑 锚过程、不锚比分（加权的前提）**：⑥读**表现/过程**——xG、控球、机会质量、失球方式、临场调度，**优先于单纯比分**。单场比分会被偶然污染（乌龙/红牌/绝杀/垃圾球），重仓比分=把噪声当信号。范例：卡塔尔1-1瑞士，比分=平(误导)、过程=瑞士68%控球/xG2.27碾压(真信号)→⑥应判"瑞士其实很强"。读过程才让⑥经得起加重。
- **(A) 本届兑现度**（每队 ±1，极端 ±2）：对比赛前纸面预期、**以过程为准**——🔥超预期/被低估 **+1**(大爆冷+2) ｜ ✅达预期 **0** ｜ ❄️低于预期/被夸大 **−1**(大崩盘−2)。
  - **关键规则·虐菜=0**：打鱼腩赢多少都算达预期(0)、信息量低（德国7-1库拉索≠变强）；**只有对强队/硬防守队的结果才有真信息**（赢=超预期、平/输=低于预期）。防"虐菜大胜"虚高本维。
  - **过程修正比分**：赢/平/输靠偶然（乌龙绝杀/红牌）的，按过程上调或下调兑现度——碾压却平=不降反升、被反杀但全程压制=少降。
- **(B) 合成 lean**：`net = A兑现度 − B兑现度` → net≥+2 强lean A ｜ +1 中lean A ｜ 0 even ｜ −1 中lean B ｜ ≤−2 强lean B。
- **(C) 出线处境修正**（动机/轮换）：争出线/必须赢 → 全力、场面更拼，不打折；**已提前出线 → 可能轮换保留主力、强度下降 → 对该队预测打折、比分波动大、平局/爆冷概率升**（末轮尤甚）。
- **权重与约束（0615加权后）**：① **实力判断上 ⑥ 权重 ≥ ①**；二者背离时**以 ⑥ 主导校正①**（不再只是"打个折"）。② **单场样本即全力实施**（第2轮1场历史就可出强 lean，不必等2场）。③ **⑥ 与盘口同向的强信号 → 可参与翻方向**；⑥ 与盘口背离 → 回盘口裁决 + 标"存疑"（防 1 场过拟合）。④ **⑥≠②**：②是赛前近况(热身/伤停)，⑥是正赛**已发生**的事实，背离时以⑥为准。
- **worked example(6/21)**：突尼斯1-5崩(−2) vs 日本残阵逼平荷兰(+1)→net+3 **强lean日本**；德国7-1虐菜(达预期0) vs 科特迪瓦1-0零封硬防厄(+1)→中lean科特迪瓦competitive=**别盲目给德国押大净胜**。

报告卡顺序（第2轮起）：五维卡 → **第⑥维卡** → 盘口修正卡（⚖五维vs盘口）。第⑥维属骨架层且权重≥①，盘口仍是独立修正层。

> **⚠️ 盘口不是维度**：盘口是独立的「修正/裁决层」，在五维(+⑥)搭出骨架后，对方向与比分做**修正比较**（见下）。报告里第⑤维只写软性，盘口单独成块，别混。

**五维(+⑥) ↔ 盘口 的权重(条件性,非固定百分比)**——两段式 + 冲突时按优先级裁决：

1. **五维搭骨架**：定方向、剧本；比分概率分布以赔率市场为基底、五维修正。
2. **盘口裁决（冲突时优先级，从高到低）**：
   - 🔴 盘口移动「**退盘 + 让球砍半 + 转小球**」三连 → **机械下修主预测**（0614 巴西教训）。
   - 🟠 **亚盘 sharp 深盘** → 压过五维的净胜球先验（0613 瑞士让2、0614 德国让3：亚盘优先于"收口"）。
   - 🟠 **sharp / moneyline 指向弱队「不败或平局」**（让球缩到 -0.5/平手、赔率向弱队收窄）→ **把"平/弱队不败"从次选扶正为主预测**。sharp 不只修净胜球，也修胜负方向。（0615 荷兰2-2日本教训）
   - ⚪ **firm 盘口（未退/未动）≠ 确认信号** → 不得作为加注或盖过五维⑤软性维度的理由。"盘口没动"是默认态，不是利好。（0614 澳大利亚2-0土耳其教训）
   - 🟡 **五维** → 盘口中性/一致时主导方向与剧本。
   - 🟢 **大小球** → 给总进球封顶。

   **⛳ 开赛前强制 checklist（提交主预测前必须逐条勾，把上面"原则"变成必过闸）：**
   1. ☐ 有「退盘 + 砍让球 + 转小球」三连？→ **有则主预测机械下修一档，不许找理由保留**
   2. ☐ sharp / 移动盘指向哪边？→ 指向弱队不败/平局，**次选扶正为主预测**
   3. ☐ 我有没有拿「firm / 盘口没退」当确认信号？→ 有则**划掉这条理由**
   4. ☐ 主预测与上面三条有冲突？→ **冲突时盘口优先**（五维只搭骨架）

**已沉淀的纪律**（写在 [`复盘台账.md`](复盘台账.md) 第一部分）：
- **降低净胜球野心**：默认往一球分差/平局收口，只有"真实速度体能错配 + 对手愿对攻"才押 2 球净胜。
- **控得住 ≠ 攻得破**：当代足球进球难是系统性的，别因控球/xG 高就押大胜（瑞士便秘、巴西破不了密防）。
- 原则：**一场不改五维框架**；规则调整由用户拍板，台账只记录待样本。

## 目录结构

```
.
├── index.html              # 主页（时间轴 / 战绩看板 / 积分榜）
├── data.js                 # 数据源：matches(预测+实际) / fixtures(72场) / groups(12组)
├── theme.css, theme.js     # 暗/亮主题（全站共享）
├── reports/                # 每场的预测报告 + 复盘报告（独立 HTML，带 OG 分享卡）
├── 复盘台账.md              # 【赛后】逐场复盘 + 跨场信号/规律（预测前必读）
├── 临场追踪.md              # 【赛前】盘口移动 + 伤停首发记录（与复盘解耦）
├── stats/                  # 数据中心（赛后技术统计沉淀，再次预测同队前先读）
│   ├── matches.json        #   真相源：每场硬数据(比分/进球/控球/xG/缺阵/预测对错)
│   ├── team_profiles.md    #   定性层：每队 进攻/防守评分 + 主帅 + 画像 + 下轮注意
│   └── README.md           #   数据中心 schema 与录入流程
├── _headers                # Cloudflare Pages：边缘缓存 + 安全响应头
└── deploy.sh               # Cloudflare Pages 发布脚本（data.js 版本戳防缓存）
```

> **文件分工**：`复盘台账.md` 只管赛后复盘；`临场追踪.md` 只管赛前盘口/首发；`stats/` 是预测引擎用的球队数据库。三者解耦。

## 更新管道（本地 → GitHub → Cloudflare，三步缺一不可）

```bash
# 1. 本地：改 data.js / reports/ / 台账 / stats/ 等
# 2. GitHub：提交并推送（所有更新都推，含 stats/ 数据中心）
git add -A && git commit -m "..." && git push origin main
# 3. Cloudflare：发布站点
bash deploy.sh
```

> - `deploy.sh` 发 index/data/theme/reports/_headers；**不发** `复盘台账.md`、`临场追踪.md`、`stats/`（只靠 GitHub 留存）。
> - Pages 与 GitHub 无自动联动；`index.html` 每次回源校验、`data.js` 带部署时间戳，静态资源走边缘缓存。

## 每日更新流程

1. **赛前**：`data.js` 的 `matches` 数组**开头**追加当日预测（`mainPred`/`altPred`）+ 报告 HTML 进 `reports/`；在 `临场追踪.md` 记初盘（盘口+伤停+主预测）。
2. **临场**：赛前刷移动盘口 / 官方首发，触发纠偏规则，更新 `临场追踪.md`。
3. **赛后**：回填 `data.js` 的 `actual` + `status`（exact/alt/direction/miss）→ 时间轴/战绩/积分榜自动重算；`临场追踪.md` 填实际+判定；`复盘台账.md` 写逐场复盘；`stats/` 入库（matches.json + team_profiles.md）。
